# War Counter R5 — Mobile AKAZE lab

Status: implementation prepared on `agent/war-counter-r5-embeddings-benchmark`.

## Goal

Measure the validated R5 AKAZE shortlist directly in the real browser/mobile lab before any production integration.

## Runtime path

1. User selects a normal War result screenshot in `docs/war-counter-lab.html`.
2. The lab lazily loads OpenCV.js 4.10.0 only when the AKAZE benchmark button is pressed.
3. Static browser assets contain the validated 450-reference AKAZE descriptor catalogue generated by GitHub Actions.
4. Ten base portrait crops are processed sequentially.
5. AKAZE descriptors are extracted with threshold `0.0008` and maximum side `320`.
6. One global Hamming KNN (`k=4`) is run against the complete descriptor catalogue.
7. Votes are aggregated by reference character with the same normalization used by the validated Python mobile-shortlist benchmark.
8. The lab renders Top candidates and per-slot extraction/matching timings.

## Safety / scope

- lab only;
- no Groq call;
- no production War Counter modification;
- no modification to `workers/msf-war-ocr/worker.js`;
- no dependency on ChatGPT temporary local storage;
- browser descriptors are generated and persisted by GitHub Actions.

## Measurements requested on iPhone

- OpenCV.js lazy-load time;
- static descriptor load time;
- AKAZE extraction time per crop;
- global matching time per crop;
- total 10-slot wall time;
- JS heap only when the browser exposes it.

The Safari memory API is optional: absence of a heap number is expected and must not block the benchmark.
